Windows Registry Change Monitoring System

A Python-based cybersecurity tool for monitoring Windows Registry changes, detecting suspicious modifications, and generating security reports.

Developer: Kushagra Dixit
Platform: Python / Windows
GitHub Repository Detailed Project Report

Project Overview

The Windows Registry Change Monitoring System is designed to monitor critical and configured Windows Registry locations and detect changes that may indicate persistence mechanisms, configuration changes, or suspicious activity.

How the System Works

  • Creates a trusted Registry baseline snapshot
  • Compares the current Registry state against the baseline
  • Detects added, modified, or deleted registry values
  • Classifies suspicious changes with rule-based detection logic
  • Records events in persistent JSONL log sinks
  • Generates structured CSV reports for analysis

Key Features

Registry Baseline

Creates a reference snapshot of configured Registry locations.

Integrity Verification

Compares the current Registry state with the saved baseline.

Change Detection

Detects ADD, MODIFY, and DELETE Registry changes.

Autorun Monitoring

Monitors Registry locations commonly associated with startup persistence.

Suspicious Change Detection

Uses rule-based indicators to identify potentially suspicious Registry modifications.

Continuous Monitoring

Continuously checks Registry state using the configured monitoring interval.

Event Logging

Records Registry changes with timestamps and detection information.

CSV Reporting

Generates structured CSV reports containing detected changes.

Monitored Registry Locations

The system monitors configured Registry locations rather than the entire Windows Registry to keep resource utilization lightweight.

HKCU\Software\Microsoft\Windows\CurrentVersion\Run
HKCU\Software\Microsoft\Windows\CurrentVersion\RunOnce
HKLM\Software\Microsoft\Windows\CurrentVersion\Run
HKLM\Software\Microsoft\Windows\CurrentVersion\RunOnce

Additional Security Subsystems Observed:

  • Windows Defender policies
  • Firewall configuration
  • Winlogon configuration
  • UAC policies
  • Other configured Windows persistence/security locations

Detection Logic

Supported Change Types

  • ADD: Detects newly registered keys or values.
  • MODIFY: Alerts on altered string payloads or configuration flags.
  • DELETE: Identifies uninstalled software references or policy removals.

Suspicious Indicators

  • Executable autorun entries (.exe, .bat, .cmd)
  • PowerShell executions and inline commands
  • Windows script interpreters (WScript, CScript)
  • HTML Applications launched via MSHTA
  • Tampering with system security & protection policies

Technical Architecture & Tech Stack

Directory Structure

├── cli.py         # Command-line interface
├── config.py      # Scan configuration & keys
├── detector.py    # Change & alert analyzer
├── monitor.py     # Continuous loop daemon
├── registry.py    # Native winreg integration
└── reporting.py   # Event logger & CSV writer

data/
└── baseline.json  # Reference snapshot

logs/              # Output reports
tests/             # Automated test cases

Technology Stack

Python: Core language logic implementation.
Windows winreg: Low-level native Registry API access.
JSON / JSONL: Baseline persistence and local event storage.
Unit Testing: Integrity validation of the analysis pipeline.

Project Limitations

  • Windows-specific implementation (cannot run on Linux/macOS).
  • Requires local Windows Registry administrative read permissions.
  • Rule-based classification engine (no ML heuristics).
  • Periodic polling interval (no real-time kernel-hooking).
  • Monitors only predefined, configured directories.
  • CLI-based execution instead of standard desktop GUI.

Future Scope

  • Web dashboard for continuous visual stream reporting.
  • Dynamic YAML threat-detection rule configurations.
  • Trace modifications back to the exact launching PID.
  • Automated email alerts using custom secure SMTP triggers.
  • Visual graphs tracking registry adjustments over time.
  • Integration with native Windows kernel notify events.
